# PRD: AX-9 — Extraction Honesty Hardening

**Status:** proposed
**Phase:** AX-9 (hardening) · **Date:** 2026-07-04 · **Author:** NF + Claude
**Related:** dogfood review `docs/reviews/2026-07-04-dogfood-iranti-next.md` (checks 2, 3, 4-caveat; fix-list items 1, 2, 5), Layer 0b PRD (the instrument this must move), Layer 0c PRD (alias learning gated on artifact extraction), master PRD G1 ("it never invents").

---

## 1. Summary

The dogfood eval broke the extractor's honesty promise in live use three ways: it **fabricated** a fact by dropping a negation ("no rate limiting decision is on record…" → a stored `decision:*` asserting the opposite), it **missed** both long em-dash-punctuated facts NF-style prose produces, and it **cannot see** bare repo-relative paths (`docs/reviews/x.md`), which silently disables alias learning for the most common developer artifact reference. This phase fixes all three in the heuristic extractor and — instrument-first — extends the bench corpus so each failure prints red before the fix and its delta prints after.

## 2. Problem & motivation

- **Fabrication (dogfood check 3, FAIL):** `DECISION_PATTERNS`' bare-noun pattern `\bdecision[:\s]+(.{3,80}?)` fires on the word "decision" anywhere in a sentence, including negated ones. Live result within ~20 turns: `decision:is-on-record-for-the-http-transport` = "is on record for the HTTP transport", extracted from the host's own post-response summary *"Told the user no rate limiting decision is on record for the HTTP transport."* This is the Mem0-class junk G1 exists to prevent, generated by the protocol itself. The bench precision metric reads 100% because the corpus contains zero negated sentences bearing category nouns — the instrument has a blind spot exactly where the live system failed.
- **Recall on real phrasing (check 2, PARTIAL root cause):** every capture terminates only at `[.,;]` within 60–80 chars. "we decided to keep PGlite as the default database engine — Postgres is opt-in through the IRANTI_DB_ENGINE env var." extracts nothing: the em-dash is not a terminator and the full clause exceeds the cap. Same fate for a "constraint: …" sentence in the same eval turn. NF writes in long dash-punctuated sentences; the extractor is structurally blind to them.
- **Bare relative paths (check 4 caveat):** `RELATIVE_PATH_PATTERN` requires a `./` or `../` prefix. `docs/reviews/2026-07-03-overnight-build.md` in prose extracts nothing — and because `extractAliases` only runs when an artifact was extracted from the same message, the Layer 0c textbook fix silently never happens for path-referenced artifacts.
- **Host-authored text provenance (NF decision, 2026-07-04):** the fabrication came from host-authored (post-response) text. NF ruled: semantic extraction should still run on host text but treat it "slightly differently — mostly as context for the nature of the information," i.e. provenance-labeled and confidence-reduced, not skipped and not full-trust.

## 3. Goals & non-goals

**Goals**
- No bare-noun category patterns can fire mid-sentence (fabrication vector closed).
- Em-dash/en-dash-punctuated clauses extract on their pattern classes.
- Bare multi-segment relative paths with a file extension extract as `referenced_file` artifacts (and can therefore carry aliases).
- Post-response host-authored `message` extraction is provenance-labeled (`host_summary_extract`) at reduced confidence (0.70), matching the existing `attendant_autowrite` posture for `currentContext`.
- Corpus gains fabrication probes (negated category-noun sentences that must extract NOTHING), em-dash gold facts, and bare-path gold facts — added, never editing existing entries.
- Every bench delta explained line-by-line; baseline regenerated in a dedicated commit per the established advancement policy.

**Non-goals**
- Any LLM/semantic negation understanding (G1; the LLM tier is OD-1/OD-2's separate track).
- General NLP negation scope resolution — the fix is pattern-level (kill the vector), not linguistic.
- Touching `iranti_search`/`iranti_query` matched flags, alias paraphrase matching, or correction supersession (Layer 0i).
- The evolving user/system assumptions-profile idea (registered as OD-6; own PRD if pursued).

## 5. Design decisions & rationale

- **D1 — Remove the bare-noun patterns `\bdecision[:\s]+…` and `\bconstraint[:\s]+…`; replace with sentence-initial label forms** `(?:^|[.!?]\s+)decision:\s+…` / `(?:^|[.!?]\s+)constraint:\s+…` (colon required, label position required). *Why:* the corpus's real positives for these patterns are label-style openers ("Decision: all new components live under src/components/ui"); the mid-sentence noun form is what fabricated. Keeping the label form preserves those hits; requiring position+colon makes "no … decision is on record" unmatchable. *Rejected:* a negation lookbehind guard on the existing pattern — negation words can sit many tokens before the noun ("no rate limiting decision"), beyond fixed-width lookbehind; enumerate-the-negators is a losing game. Precision over recall says kill the vector.
- **D2 — Same treatment for `\brequirement[:\s]+…`** (constraint set) — same bare-noun shape, same fix, even though it hasn't fabricated yet.
- **D3 — Add `—`, `–`, and ` - ` (spaced hyphen) to every capture-terminator class** (`[.,;]` → `[.,;]|—|–|\s-\s`), keeping the length caps unchanged. *Why:* dashes delimit clauses in real prose exactly like commas; the capture then ends at the dash and stays under the cap. Unspaced hyphens are NOT terminators (they appear inside identifiers like `dogfood/report-1`, `qwen2.5:3b`). *Rejected:* raising the 60–80-char caps — longer captures produce worse keys and were capped deliberately (AX-1's 80-char key cap).
- **D4 — Bare relative paths: new pattern requiring ≥2 segments AND a dot-extension on the final segment**, e.g. `(?<![\w./\\-])[\w-]+(?:[\\/][\w.-]+)+\.[A-Za-z0-9]{1,8}\b`, applied after URL-stripping and deduped via the existing `seen` set. *Why the extension requirement:* prose like "input/output" or "and/or" must not become artifacts; an extension is the deterministic tell that this is a file. *Rejected:* extending `RELATIVE_PATH_PATTERN` itself (its `./`-anchored form is correct for what it claims) and directory-path support without extensions (precision risk; a missed dir-path is cheaper than junk).
- **D5 — Host-authored text: extract, but label and demote (NF's ruling).** PRD-review correction: `attend.ts` has exactly ONE `extractAndStore(input.message, …)` call, firing on every non-mid-turn phase — there is no pre-existing "post-response message call" to modify. The implementation therefore adds a phase branch AT that single call site: `phase === "post-response"` → pass `sourceOverride: "host_summary_extract"`, `confidenceOverride: 0.70` (the same override mechanism `attendant_autowrite` already uses for `currentContext`); any other phase → no overrides (user-authored text stays full-trust). Getting this branch wrong in either direction is the named risk: demoting pre-response would silently downgrade genuine user facts; skipping the branch leaves fabrications at user-grade confidence. Pinned by a two-sided test (§7). *Why:* keeps the write path alive (host summaries do carry durable facts) while making provenance auditable and confidence honest — "context for the nature of the information." *Rejected:* skipping post-response extraction entirely (loses real facts; NF ruled against) and status quo.
- **D6 — Instrument-first: harness gains a fabrication dimension, then corpus additions land BEFORE the fix commits.** PRD-review correction: the harness structurally cannot express "this message must extract nothing" today — `goldFacts` is an allow-list, `scoreExtraction` ignores extra stored facts, and `CorpusProbe.negative` scores retrieval, not extraction. So this phase adds a scorer/type extension: an optional per-persona `fabricationProbes: [{ text, note }]` corpus array; the runner feeds each probe text directly through the deterministic extractor and any extracted fact is a violation. New metric `extraction.fabricationRate` (violating probes / total probes, lower is better) printed alongside recall/precision and recorded in the baseline (diff code treats the field as absent-tolerant for old baselines). With that in place, corpus additions (fabrication probes incl. the live incident's sentence shape; em-dash golds; bare-path golds) land first and print red — fabricationRate > 0, recall misses — and the fix commit prints them flipping. Existing messages/golds/probes byte-unchanged (insertion-only diff).
- **D7 — Baseline advancement:** regenerate `bench/baseline.json` once, in a dedicated final commit, with every metric delta explained in the commit message (established overnight policy; also satisfies the standing project rule to run bench before merging extraction changes and record deltas).

## 9. Risks & open questions

- **Removing bare-noun patterns may drop real recall** on mid-sentence "decision …" phrasings the corpus doesn't currently reward. Accepted deliberately (precision over recall); the bench delta will quantify it and the LLM tier (OD-1/OD-2) is the sanctioned recall path.
- **The spaced-hyphen terminator ` - ` could truncate values that legitimately contain it** (rare in facts; lists mostly). Accepted: truncation at a clause boundary beats extraction failure; unit-pinned.
- **Extension-required paths miss extensionless files** (`Makefile`, `Dockerfile`, bare dirs). Known, disclosed; a curated whitelist of famous extensionless filenames is a possible follow-up, not smuggled in here.
- **`host_summary_extract` facts still enter the same store** and can still surface `matched: true`. Demotion is provenance+confidence only; whether confidence should gate `matched` eligibility is a Layer 0f follow-up question, noted for OD-6's fervor-modulation idea.
- **Fabrication probes only cover the pattern classes we know about.** The probe set is a floor, not proof of non-fabrication; future incidents add probes (same policy as ai-mem negative probes).
