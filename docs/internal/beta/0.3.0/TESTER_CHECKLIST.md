# Tester Checklist - Iranti Closed Beta v0.3.0

Use this as the tester-facing checklist for asynchronous beta participants.

## Core Checklist

1. Install Iranti using the provided setup steps.
2. Connect it to the host or tool you already use for real work.
3. Use it on a real project or real problem, not a toy prompt.
4. Use it across at least 2-3 separate sessions.
5. If possible, test it across more than one day.
6. If possible, test it across more than one host, tool, or agent.
7. Try at least one "resume previous work" scenario.
8. Try at least one "handoff between tools or agents" scenario.
9. Notice whether Iranti reduces repeated re-explaining.
10. Write down setup friction as soon as it happens.
11. Report any case where memory is missing, wrong, duplicated, stale, or misleading.
12. Pay attention to whether it is clear:
    - when Iranti writes
    - when Iranti recalls
    - what it is remembering
    - whether you trust it
13. Complete the feedback form after your final session.
14. If requested, share screenshots, logs, or a short writeup of failures.

## What To Evaluate

Ask testers to judge:

- setup clarity
- trust and reliability
- cross-session usefulness
- cross-tool usefulness
- failure recovery
- whether it feels worth keeping in their workflow

## Minimum Useful Beta Run

If a tester is short on time, the minimum useful run is:

1. one setup session
2. one real work session
3. one later resume session
4. final feedback form

Anything less mostly tests onboarding, not continuity.

## What To Ask Testers To Record

If they hit a problem, ask them to capture:

- what host/tool they were using
- what they expected Iranti to remember
- what it actually returned or failed to return
- whether the failure was setup, recall, trust, or host-integration related
